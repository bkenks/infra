# How the docker stacks work

Every Docker Compose stack is one field of a single CUE value, `stacks.<name>`. CUE renders
each stack to `stack/<category>/<name>/compose.yaml`, beside the stack's runtime files. The rendered
files are committed, and Komodo deploys them from that directory. The deploy pipeline never runs CUE.

## Layers

| Layer          | What                                                                                                                                                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Compose schema | Upstream Compose JSON Schema imported as `#Compose`, plus a generated regex of valid service keys. Regenerated by a mise task, never edited by hand.                                                                          |
| `#Stack`       | House spec unified with `#Compose`: derived `container_name`, network and volume names, default `restart` and `logging`, `#ref` handles, a closed service key set, and service networks checked against the stack's networks. |
| snippets       | Shared definitions beside `#Stack`: `#Domain`, `#Mount`, `#Label`, `#Health`.                                                                                                                                                 |
| stacks         | One file per stack, each defining `stacks: <name>: S={...}`.                                                                                                                                                                  |
| `store`        | Cross-tool data (hosts, shared external networks, host paths) embedded from YAML and read by Ansible too.                                                                                                                     |

## Referencing things

- **Itself:** a service alias, e.g. `app: Svc={ _port: 8000, expose: [Svc._port] }`.
- **A sibling in the same stack:** the stack alias, e.g. `S.services.db.#ref` for the
  hostname, `S.volumes.data.#ref` for a mount source, `S.networks.default.#ref` for a
  network.
- **Another stack:** the full path, e.g. `stacks.komodo.services.app._port`.

Fields that start with `_` are hidden and definitions start with `#`. Neither reaches the
rendered YAML, so a stack can carry ports, endpoints, and helper values beside its Compose
fields. Hidden fields are scoped to their package, so anything `schema/stack` hands to the
stacks is a definition.

## Upstream inputs

vendir vendors every upstream input into `vendor/`, pinned in `vendir.yml` and locked in
`vendir.lock.yml`. To bump one, edit its ref and run `vendir sync`. `cue:update` syncs the
Compose spec and regenerates the CUE schema from it.

## Workflow

1. Edit a stack's CUE file.
2. Run `mise run cue:vet` from this directory.
3. Run `mise run cue:render` from this directory. It writes every `compose.yaml` and
   checks each one with `docker compose config`.

The pre-commit hook runs both steps and stages the rendered files.

Commands: `mise tasks`. Per-stack notes: `components/`. Decisions: `adr/`. Events: `log/`.
